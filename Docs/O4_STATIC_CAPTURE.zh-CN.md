# O4 静态姿势采集

适用于“摆好人偶，再确认一个姿势”的流程。原有 Live / Body35 / Full44 通道继续保留。新静态模式使用 41 个测量轴和 3 个固定骨盆槽；不根据上一姿势猜多圈位置。

## 使用

1. 关闭此项目的 UE 编辑器后运行 Scripts/BuildPoseDoll.ps1，再打开项目。新源码已在隔离工程编译和测试；正在运行的原编辑器不会自动加载新 DLL。
2. 首次安装模拟器依赖运行 Scripts/SetupSimulator.ps1。启动静态源：
   powershell -ExecutionPolicy Bypass -File Scripts/StartSimulator.ps1 -Static
3. 打开 UE 的 PoseDoll Lab 面板，点击“连接静态源”；在 Sequencer 中打开目标序列，选择 Manny，绑定目标。
4. 摆好模拟器姿势，点击“采集当前姿势”。等待稳定后保留预览；也可用“采集并写入当前帧”一次完成。只有成功写帧后才推进帧号。
5. 修改时间、目标、蒙版、接触/放置设置或执行 Undo，会取消等待中的事务。可以点击“取消采集”。已经确认的历史姿势继续显示，确认时间不会刷新为实时新帧。
6. “静态 Clutch”以已有快照和当前动画为基准，生成相对编辑快照，再用 Capture 写入。必须先取得一个有效源快照。

UI 里的时间是 UE 确认时间，不是两台机器同步后的硬件时间。固定骨盆槽不提供整机在场景中的位置；场景放置沿用 Placement 功能。

## 当前工程默认值

活动采样约 10 Hz，带少量周期抖动；单次完整扫描不超过 100 ms。至少 6 次扫描，所有轴共同覆盖至少 500 ms（正常约需 7 次扫描）；峰峰值 ≤0.30°、回归漂移 ≤0.20°/s；提交时最终扫描年龄上界 ≤200 ms；请求总超时 3 s。

这些是审查建议的初始软件参数，尚非实物验收数据。它们不要求恢复 60 Hz/8 ms/14 ms 的旧动态指标。有限次采样不能证明两次扫描之间没有短暂运动，周期抖动也不能消除所有混叠。

## 已实现的行为

- 请求 UUID、网关/节点/远端 boot、scan_id、配置与校准哈希全程绑定；CRC32 验证报文。
- 最后一次完整扫描作为快照；不拼接逐轴缓存，不把 missing/fault 变成合法零值。
- uint64 时间以十进制字符串传输，duration 为 uint32 微秒，拒绝超范围和截断。
- 工作线程只处理有界网络队列；编辑器主线程检查目标、时间、状态，再原子写入键。
- Native Control Rig 控制值、开关与骨骼回读失败时回滚；Undo/Redo 后重建专用 Rig 运行实例，保留曲线。
- 历史快照不会在 250 ms 后被旧 Live 新鲜度规则抹掉；同一快照只能写入一次。

## 测试与边界

reports/o4/DELIVERY.json 是软件证据入口，包含精确源文件哈希、构建和原始报告。真实 UE 编辑器的输入仍是模拟 TCP 源；没有把模拟器接收结果当成实物硬件测试。

test_static_capture_o4.py 和 test_static_reopen_o4.py 只用于专门的隔离测试工程，会建立 /Game/PoseDollO4/<run>/ 测试资产。不要在有未保存工作的编辑器里直接运行这些测试脚本。

硬件实验与 UE 插件分别位于两个仓库。当前硬件 O3 固件仍使用原协议；PDS1 硬件网关适配、STM32 外设驱动和上电/掉电台架测试尚未完成。

## 构建兼容性补充

若旧版报 PoseDollStatic.cpp 的 U64 宏参数过多，这是静态协议解析函数与 OpenSSL 宏在 Unity 合并编译中重名。后续大量类型/语法错误是该首错的连锁反应。已改用专用函数名，不需要更换 SDK。

隔离工程的自适应独立编译不能覆盖提交后的合并编译。回归时可运行 Scripts/BuildPoseDoll.ps1 -VerifyUnity，强制合并编译并关闭自适应排除；正常构建仍可使用原命令。

2026-09-24 已在实际 DollSimulation 项目验证强制 Unity 构建成功，生成的插件 DLL 通过 4 组 PoseDoll 原生自动化测试。日志位于本机 reports/o4/unity_fix/；本补充不改写 O4 首次交付时的源码包与证据。
